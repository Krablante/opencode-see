# Разработка

[English](./CONTRIBUTING.md) · [Русский](./CONTRIBUTING.ru.md) · [Главная](./README.ru.md)

Объясни, что и зачем меняешь. Рецензенту не нужно восстанавливать причину
из большого автоматически написанного текста.

Для исправления ошибки:

1. Воспроизведи поведение на небольшом полезном примере.
2. Измени минимальную совместимую часть.
3. Добавь или поправь существующий тест, который защищает контракт.
4. Выполни `npm run check`.
5. Объясни компромисс в pull request.

Перед крупной функцией или зависимостью открой issue. Проект остаётся небольшим:
браузерный фреймворк, SDK провайдера, авторизация, индекс картинок и фоновый
сервис требуют измеримой необходимости.

Не включай в Git секреты, частные пути, рабочую конфигурацию, личные картинки
и топологию машин. Демонстрационные материалы воспроизводятся на одноразовых
локальных данных через `npm run demos`.

## Разработка и проверка

```bash
npm ci
npm run check
```

OpenCode загружает `src/index.ts` напрямую; компиляция и упаковка не нужны.
Единственная зависимость выполнения — `@opencode-ai/plugin`. Защищай важное
поведение существующими тестами, без нового тестового окружения. CI выполняет
те же проверки на Node.js 22. Изменения браузерных и провайдерных границ также
требуют прицельной проверки настоящего сценария.

`npm run demos` пересоздаёт иллюстрации из одноразовых локальных картинок и
настоящего снимка localhost-страницы. Нужны FFmpeg с фильтром ASS, DejaVu Sans /
Sans Mono и Chromium. Для нестандартных путей есть
`OPENCODE_SEE_DEMO_FONTS_DIR` и `OPENCODE_SEE_CHROMIUM`. Посмотри оба GIF после
генерации. Версии браузера и FFmpeg влияют на байты; побайтовое совпадение таких
материалов не годится как требование CI. Временные входные данные удаляются.

## Документация и языки

README представляет продукт и описывает установку. Четыре темы руководства —
использование, настройка, эксплуатация и архитектура. Каждое объяснение живёт
в своей странице; из остальных ставятся ссылки. Разработка описана здесь,
сообщения об уязвимостях — в SECURITY, история версий — в CHANGELOG.

Языковые версии лежат рядом: `topic.md` — английская, `topic.ru.md` — русская.
То же правило действует для README, CONTRIBUTING, SECURITY и CHANGELOG.
Темы совпадают, ссылки ведут на язык читателя. Оригиналы LICENSE и NOTICE
остаются основными юридическими текстами.

Для нового языка добавь соответствующие страницы с языковым суффиксом,
например `.uk.md` или `.de.md`, и расширь переключатели языка. Переписывать
двуязычный движок или генератор не придётся: их здесь нет. При изменении
поведения обновляй смысл во всех существующих версиях вместе с кодом.
Одинаковая структура предложений не требуется.

Поставка идёт только через GitHub. Не публикуй пакет в npm. Теги релизов должны
указывать на проверенный код, описание выпуска — совпадать с историей изменений.
Сохраняй пометку private у пакета: она не ограничивает лицензию и загрузку
локального плагина.
